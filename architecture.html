Enterprise AI Agent Platform

Kontrollált, auditálható vállalati AI-ügynök platform. A Control Plane kormányoz (governance, ticketek, IAM, audit, agent-registry), a Dispatcher izolált Harness runtime-okban futtatja az ügynököket, minden modell- és eszközhívás a platform Gateway és Tool-Broker kapuin keresztül, hash-láncos audittal megy.

Végpontok közti adatfolyam — egy ticket élete

Ticket létrejön

Operátor a Control Plane boardon vagy egy API-kliens ticketet hoz létre. A TicketService felveszi az állapotgépbe, az AuditChain hash-elt bejegyzést ír.

Dispatcher kiválaszt

A DispatcherService batch-eli a findReadyForDispatch ticketeket, ellenőrzi a napi budget-et (maxCalls/maxTokens), és lock-tokent ad ki.

Harness indul

A választott launcher (docker-local vagy cloud-run-job) elindítja a konténert a ticketId + lockToken + agentVersion környezeti változókkal.

Agent-loop fut

A harness behúzza a ticket-kontextust (/api/v1/agent/tickets/[id]), majd lépésenként gondolkodik. Az egress-guard csak a platform-végpontokat engedi.

Eszközhívás a Tool-Brokeren át

KB-keresés / konnektor: /api/v1/agent/tools → ToolBrokerService. Csak engedélyezett eszközök, citált találatok, minden hívás ToolCall-ként auditálva.

Modellhívás a Gatewayen át

/api/v1/gateway/v1/chat/completions → ModelGateway. Provider-választás (ChatGPT OAuth / Gemini / helyi Gemma), ticket-plafon, ModelCall audit.

Kontrollált írás (Write Gate)

Ha az ügynök írni akar, write-gate tokent kell beváltania — lejáró, hatókörös engedély, így nincs ellenőrizetlen mutáció.

Visszajelentés & lezárás

A harness a /api/v1/harness/tickets/[id]/complete callbackre küldi az eredményt (callback-token védve). A ticket állapota frissül, az audit-lánc lezárul, az eredmény (pl. A0 HTML-riport) a Sandboxban megtekinthető.

  autonumber
  actor OP as Operátor
  participant CP as Control Plane UI
  participant ACT as Server Actions
  participant TKT as TicketService
  participant AUD as AuditChain
  participant DISP as Dispatcher
  participant DOCK as Docker / Cloud Run Job
  participant HRN as Harness (agent-loop)
  participant MCP as MCP Bridge
  participant TBROK as ToolBroker
  participant GW as ModelGateway
  participant LLM as LLM Provider
  participant WGS as WriteGate
  participant HCB as Harness Callback API

  OP->>CP: Ticket létrehozása (kérdés / feladat)
  CP->>ACT: createTicket()
  ACT->>TKT: create(payload)
  TKT->>AUD: auditLog(TICKET_CREATED, hash)
  TKT-->>ACT: ticket { id, state: READY }
  ACT-->>CP: ticket megjelenik a boardon

  Note over DISP: Batch-loop (cron / trigger)
  DISP->>TKT: findReadyForDispatch()
  TKT-->>DISP: [ticket]
  DISP->>DISP: budget check (calls/tokens/nap)
  DISP->>TKT: lockTicket(lockToken)
  DISP->>AUD: auditLog(DISPATCH_START)

  alt docker local
    DISP->>DOCK: docker run --env ticketId lockToken agentVersion
  else Cloud Run Job
    DISP->>DOCK: jobs.run(ticketId, lockToken, agentVersion)
  end

  DOCK->>HRN: job-entrypoint boot
  HRN->>MCP: fetch ticket context
  MCP->>ACT: GET /api/v1/agent/tickets/{id}
  ACT-->>MCP: ticket + recipe + memory

  loop agent lépések
    HRN->>MCP: tool_call(kb_search, args)
    MCP->>TBROK: kbSearch(query)
    TBROK->>AUD: auditLog(TOOL_CALL)
    TBROK-->>MCP: [{snippet, sourceRef, citáció}]
    MCP-->>HRN: tool result

    HRN->>MCP: chat/completions(messages)
    MCP->>GW: POST /api/v1/gateway/v1/chat/completions
    GW->>GW: ticket plafon ellenőrzés
    GW->>LLM: request (ChatGPT / Gemini / Ollama)
    LLM-->>GW: completion
    GW->>AUD: auditLog(MODEL_CALL, tokens)
    GW-->>MCP: completion
    MCP-->>HRN: assistant message

    opt kontrollált írás szükséges
      HRN->>MCP: write_gate_request()
      MCP->>WGS: issueToken(scope, ttl)
      WGS->>AUD: auditLog(WRITE_GATE_ISSUED)
      WGS-->>HRN: writeGateToken
      HRN->>MCP: commit_write(token, payload)
      MCP->>WGS: redeemToken(token)
      WGS->>AUD: auditLog(WRITE_GATE_REDEEMED)
    end
  end

  HRN->>HCB: POST /api/v1/harness/tickets/{id}/complete (callback-token)
  HCB->>TKT: completeTicket(result)
  TKT->>AUD: auditLog(TICKET_COMPLETE, hash)
  TKT-->>HCB: ok

  Note over CP: Operátor látja a kész ticketet
  OP->>CP: riport megtekintése (Sandbox)
